# 《说话有谱》比赛汇报 PPT 素材

> 用途：将本文件交给 GPT 或 PPT 制作工具，生成 8–12 页比赛汇报演示文稿。
>
> 在线 Demo：https://shuohua-youpu.vercel.app

## 1. 封面

**说话有谱**

让每句话出口前，心里都有谱

副标题：面向职场高压沟通的 AI 对话预演工具

汇报关键词：职场沟通｜AI 预演｜三种策略｜对方反应

## 2. 项目背景：职场沟通的真正难题

很多人并不是“不知道怎么写一句话”，而是不确定说出口之后会发生什么：

- 拒绝加班，担心被认为不配合；
- 向领导汇报错误，担心影响信任和绩效；
- 和客户协商延期，担心关系恶化；
- 提出不同意见，担心被追问、否定或贴标签；
- 争取资源、请假或拒绝额外任务时，不知道底线如何表达。

通用 AI 往往直接输出一段漂亮话术，但用户需要自己组织背景、判断关系和补充提示词。即使拿到第一句，也仍然不知道对方追问或拒绝时该怎么接。

## 3. 产品洞察与一句话定位

### 核心洞察

用户需要的不是“代写”，而是一次低风险的沟通排练。

### 一句话定位

**说话有谱是一款面向职场高压沟通的 AI 对话预演工具：先诊断用户的顾虑和底线，再给出三种沟通策略，并预演对方可能的回应。**

### 产品承诺

在重要对话发生前，让用户从“不敢说”变成“心里有谱”。

## 4. 目标群体

### 首批目标用户

工作 0–5 年、经常需要面对上级或客户，但缺乏高压沟通经验的年轻职场人。

### 典型用户画像

小林，工作两年，需要向强势领导说明周末无法加班。她知道自己的原因，却担心表达不当影响评价；她真正想知道的是：可以怎么说、对方可能怎么回、自己下一句如何守住边界。

### 高频场景

拒绝加班、项目延期、汇报错误、临时请假、争取资源、表达不同意见、拒绝超出职责范围的任务、与客户协商交付条件。

### 用户 JTBD

> 当我面对一场可能影响关系或利益的职场对话时，我希望在开口前看到不同说法及其可能后果，以便选择最符合自己底线的方案。

## 5. 核心流程：三幕式对话排练

### 第一幕·定角

选择沟通对象（领导、甲方/客户、同事）、性别形象和性格标签。支持“强势、严谨、随性、佛系、多疑”等预设，也支持自定义性格描述。

### 第二幕·起因

用户用自然语言描述沟通困境。系统将场景作为必填信息；AI 在信息不足时最多追问两轮，帮助澄清真实顾虑和底线。追问可以跳过，降低使用压力。

### 第三幕·排演

系统生成委婉、直接、迂回三种策略。用户翻开话术卡后，可以看到对方的“可能反应”、对应情绪和下一句应对提示。

### 核心 Aha 时刻

**翻开话术卡，看到“对方可能这样回”以及“我可以如何接住”。**

这一步把产品从文案生成器变成了真正的对话预演工具。

## 6. 产品功能亮点

- 关系、性别、性格组合化设定，建立清晰沟通上下文；
- 一键载入主演示场景，比赛现场可重复、稳定演示；
- 沟通困境必填，追问可选，兼顾结果质量与使用自由度；
- 最多两轮自然追问，不把用户变成填写问卷；
- 三种策略不是同义改写，而是对应不同关系风险和表达取舍；
- 话术卡翻面查看对方可能回应和接话建议；
- 真实 AI 与离线预设双模式，超时或断网时仍可完成演示；
- 复古羊皮纸、撕拉边缘和舞台幕次，形成可识别的剧场化体验。

## 7. 与其他产品的差异化

| 对比维度 | 通用 AI / 普通文案工具 | 说话有谱 |
|---|---|---|
| 用户输入 | 依赖用户自己写完整提示词 | 用角色设定和自然语言逐步引导 |
| 解决问题 | 生成一段表达文本 | 帮用户做沟通决策和风险预演 |
| 输出形式 | 通常只有一版答案 | 委婉、直接、迂回三种策略 |
| 对话深度 | 生成第一句后结束 | 诊断顾虑，必要时最多追问两轮 |
| 后续应对 | 用户自己猜对方会怎么回 | 预演对方可能回应并给出接法 |
| 体验记忆点 | 文本编辑器式交互 | 三幕剧场、翻卡和角色反应 |
| 长期潜力 | 每次重新描述关系 | 可扩展沟通对象档案和实际反馈学习 |

一句话总结：**通用 AI 帮你把话写出来，说话有谱帮你把整场对话排练一遍。**

## 8. 技术方案（体现专业性但不过度深入）

### 技术栈

- 前端：Next.js 16、React 19、TypeScript；
- 样式与视觉：CSS Modules + 全局 CSS，SVG 撕纸蒙版、纹理图片和响应式布局；
- 数据校验：Zod，对 AI 输出做结构和枚举校验；
- 服务端：Next.js Route Handler，统一处理 `/api/coach` 请求；
- 部署：Vercel，支持 Next.js 页面和服务端 API 同时运行；
- 代码托管：GitHub，仓库为 `lileifan/shuohua-youpu`。

### 前端架构

界面不是多个互相独立的页面，而是由一个清晰的流程状态机驱动：

`setup → describe → clarifying → generating → results`

异常时进入 `fallback`。这样可以保证幕次导航、按钮状态、输入内容和结果展示同步变化，避免用户在错误阶段重复提交。

### AI 请求与输出协议

前端把角色、性格、沟通困境和追问记录组装成结构化请求，发送到服务端。服务端负责：

1. 选择真实 AI 或离线预设模式；
2. 注入沟通教练的行为约束；
3. 解析模型返回内容；
4. 校验结果字段、策略枚举和三张卡片数量；
5. 校验失败、超时或网络异常时切换预设结果。

AI 输出包含三类策略，每类包含：策略名称、可直接使用的话术、策略说明、对方可能回应、情绪反应和下一句应对提示。结构化协议让前端不依赖模型自由发挥的排版文本。

### 稳定性与安全

- API 密钥只保留在服务端环境变量，不进入浏览器和 GitHub；
- `.env.local` 被 Git 忽略，仓库只提供 `.env.example`；
- 真实 AI 失败时自动或手动切换离线预设，保障比赛演示；
- 生成前后都有输入与输出校验，降低空结果、格式错乱和重复提交风险；
- 产品文案使用“可能反应”“一种应对预案”，不宣称精准预测他人。

## 9. 视觉与交互设计

视觉语言采用“复古剧本 + 舞台排演”：

- 羊皮纸作为内容承载面，边缘使用不规则撕裂、缺口、卷翘和阴影；
- 中心底色保持浅暖色，保证汉字正文和输入框可读；
- 顶部以“第一幕·定角 / 第二幕·起因 / 第三幕·排演”建立进度感；
- 角色标签、火漆红按钮和策略卡强化舞台道具感；
- 翻卡交互把“对方可能反应”从说明文字变成可探索的戏剧动作。

设计目标不是单纯装饰，而是让用户记住产品的核心隐喻：**我正在上台前排练一场重要对话。**

## 10. 商业价值与产品化路径

### 比赛阶段

B2C 个人产品：免费完成基础对话预演，用完整闭环证明用户价值。

### 赛后 P2

- 增加同事、下属、跨部门协作方等角色；
- 场景包、历史剧本和长期沟通对象档案；
- 用户回填真实回应，比较“预演”和“实际”；
- 语气微调、连续角色扮演和多轮训练；
- 更多预演次数、专业场景包等个人付费能力。

### 远期 B2B

面向企业新人培训、管理者沟通训练和销售客户沟通演练，提供团队场景库与训练效果评估。

## 11. 演示脚本（约 2–3 分钟）

1. 进入第一幕，选择“领导 / 男 / 强势”；
2. 点击“一键载入主演示场景：周末加班”；
3. 进入第二幕，展示已载入的沟通困境；
4. 展示 AI 追问，回答一轮或点击“跳过这个问题”；
5. 进入第三幕，展示委婉、直接、迂回三张策略卡；
6. 翻开其中一张，强调“对方可能这样回”与“你可以如何接住”；
7. 用一句话收束：**它不只帮你写一句话，还帮你预演说出口之后怎么办。**

备用场景：甲方/客户延期。若网络或模型异常，使用离线预设继续演示。

## 13. 局限与下一步

当前版本的 AI 结果仍是“可能的预案”，不能替代真实沟通判断；目标用户频率、留存和付费意愿仍需通过用户测试验证。

下一步优先验证三件事：

1. 用户是否愿意在真实沟通前反复使用；
2. “预演对方反应”是否比单纯生成话术更有价值；
3. 用户最愿意付费的是场景包、对象档案还是连续训练。
